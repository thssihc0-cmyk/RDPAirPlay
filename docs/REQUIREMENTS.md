## 1. 文档目的

本文档定义 iOS 端 RDP 远程控制应用 **RDP AirPlay**（仓库名 `RDPAirPlay`）的产品范围、功能需求、非功能需求、验收标准与分期交付。实现进度见 [DEVELOPMENT.md](DEVELOPMENT.md)。用户操作说明见 [USER_GUIDE.md](USER_GUIDE.md)。

## 2. 产品概述

### 2.1 一句话描述

在 iPhone / iPad 上通过 RDP 远程控制 Windows 电脑：画面可投到 AirPlay 电视（扩展模式）；支持 Microsoft Remote Desktop 风格触控与键盘；会话中可修改分辨率；弱网下可降为灰度或黑白仍可操作；支持远程系统与应用音频；支持在 iOS 上接听远程会话中的微信等语音通话（双向可听可说）。

### 2.2 目标用户

- 外出时需要操作家用或办公 Windows 的个人用户
- 需要把远程桌面投到电视 / Apple TV，手机当触控板的用户
- 在地铁、弱 4G 等高延迟、高丢包网络下仍要完成点击类操作的用户
- 电脑上挂着微信，人在外面需要用手机接听微信语音/视频来电的用户

### 2.3 典型场景

| ID | 场景 | 成功标准 |
|----|------|----------|
| S1 | 外出办公 | Wi-Fi / 蜂窝下打开远程桌面，浏览、打字、点击可用 |
| S2 | 电视投屏 | 电视全屏桌面，手机大触控板 + 底部键盘/功能键 |
| S3 | 极差网络 | 灰度或黑白 + 降分辨率/帧率后仍能点「接听」等按钮 |
| S4 | 远程接听 | 远程微信来电，iOS 听到铃声，点接听后双方能正常说话 |

## 3. 范围

### 3.1 必须包含（MVP / P0）

- iOS 16+ RDP 客户端，连接 Windows 10/11 远程桌面（默认端口 3389）
- 用户名/密码认证；密码存 Keychain；NLA 作为默认安全协商
- 触控（单击、双击、长按右键、滚动）、软键盘与常用修饰键
- **鼠标指针 / 直接触控** 双模式（对齐 MS Remote Desktop）
- 连接前选择分辨率；会话中修改分辨率（协议支持则动态协商，否则安全重连）
- 本机视口双指缩放（1×–4×）；鼠标指针模式下以光标为锚点缩放；**仅放大后可拖动画布**
- 色彩模式：全彩 / 灰度 / 黑白；弱网自适应（可手动锁定模式）
- 远程音频播放（系统声、应用声、微信铃声）
- iOS 麦克风重定向到远程会话，供微信等应用采集
- 会话配置的保存与列表管理

### 3.2 P1 必须包含

- AirPlay / 外接 `UIScreen`：**扩展模式**（桌面在第二屏，本机为大触控板 + 底部操作区）
- 外接 Scene 接管（`ExternalDisplaySceneDelegate`），默认扩展而非镜像
- 第二屏断开后画面回到本机，RDP 不断开
- 连接失败原因提示与自动重连
- 首次连接「音频设备检测」向导

### 3.3 明确不做（本期）

- 远程打印、剪贴板传大文件、磁盘映射
- RD Gateway / 堡垒机（可列入 P2）
- Windows 多显示器完整映射（P0/P1 单屏）
- 被控端为 macOS / Linux
- 将微信来电接入系统 CallKit 原生电话界面
- 未经授权的第三方主机扫描、爆破或绕过认证

### 3.4 合法与安全边界

仅允许用户连接其有权使用的主机。产品不提供攻击、未授权访问或绕过登录的能力。

## 4. 角色与术语

| 术语 | 含义 |
|------|------|
| 被控端 / 主机 | 运行 Windows、开启远程桌面的电脑 |
| 会话 | 一次已认证的 RDP 连接 |
| 第二屏 | AirPlay 或有线外接屏幕 |
| 扩展模式 | 电视独立显示远程桌面，手机为触控板（非镜像） |
| 鼠标指针模式 | 本地显示光标，点击在光标处生效；缩放以光标为锚点 |
| 直接触控模式 | 触摸点直接映射到远程桌面坐标 |
| 上行音频 | iOS 麦克风 → 远程 Windows 录音设备 |
| 下行音频 | 远程播放设备 → iOS 听筒/扬声器 |

## 7. 架构约束（需求级）

```
iOS App（SwiftUI + UIKit 画布 / 触控板 / 键盘 / 弱网 / AirPlay 分流）
        │  rdp_bridge → FreeRDP
        │  图形 + 下行音频 + 上行麦克风 + 输入
        ▼
Windows 主机（桌面、微信、RDP 服务）
```

- 远程桌面交互使用 UIKit 画布，避免 SwiftUI 变换导致坐标偏移。
- 外接屏使用独立 Scene + UIWindow，帧与光标与主会话同源。
- P0 不强制 Windows Agent；麦克风无法被微信使用时 P1 评估虚拟声卡 / Agent。

## 8. 已知约束

1. 微信是应用内 VoIP；接听 = 点远程 UI + 双向音频。
2. 部分 Windows 默认录音设备导致微信无声，需要向导或 Agent。
3. 弱网 + RDP + 微信编码叠加延迟，需求为可通话而非运营商质量。
4. iOS 后台对麦克风限制严格；P0 要求通话时保持前台。
5. AirPlay 扩展依赖系统分配外接 Scene；须 App 前台且 SceneDelegate 及时建窗。
