## 1. 项目定位

**RDP AirPlay**（仓库名 `RDPAirPlay`）是面向 iOS 的远程桌面控制产品，协议采用 Microsoft RDP，被控端为用户本机或办公 Windows。产品差异化不在「再做一个远程桌面」，而在三件事同时成立：

- 手机可操作，画面可到 **AirPlay 电视扩展**（非简单镜像）
- **最差网络**下通过降分辨率、降帧、灰度/黑白仍能完成点击
- **双向音频**足够支撑远程微信等应用的接听与通话

本说明描述「为什么做、怎么拆、怎么验、有什么坑」。需求条目、优先级与验收用例以需求文档为准。

## 3. 要解决的问题

| 痛点 | 产品回应 |
|------|----------|
| 出门无法操作家里/公司电脑 | 标准 RDP 客户端，保存主机与凭据 |
| 手机屏小、要给旁人看桌面 | AirPlay **扩展**：电视看桌面，手机当触控板 |
| 地铁、弱 4G 花屏卡死 | 自适应码率 + 灰度/黑白锁定 |
| 电脑挂着微信，来电接不到 | 远程点接听 + 麦克风/扬声器重定向 |
| 小屏操作 Windows 不顺手 | MS RDP 风格双模式 + 完整软键盘 |

不解决：未授权入侵、替代运营商电话、把微信变成 CallKit 原生来电、第一期做全平台被控端。

## 4. 成功标准（项目级）

项目在 P0 结束时视为「技术闭环成立」，当且仅当：

1. 测试机 Windows 上微信来电，iOS 能听到铃声。  
2. 用户在 iOS 画面上点接听。  
3. 对方能听到 iOS 麦克风；用户能听到对方；可持续对话至挂断。  
4. 同一版本在人为弱网下，灰度或黑白模式仍能完成该点击。

AirPlay 扩展 UI 与触控板已实现；P1 验收重点转为 **真机全链路**（Scene 分配、弱网、音频）。若第 1–3 条因 Windows 默认录音设备失败，允许 P0 带「音频向导 + 已知限制」结项，但必须在一周内给出 Agent/虚拟声卡的 P1 方案。

## 5. 技术方案摘要

### 5.1 控制面

Swift 管理主机列表、连接参数、色彩锁定、分辨率、外接屏布局、鼠标模式。密码只进 Keychain。会话中枢为 `RDPSessionController`。

### 5.2 数据面

FreeRDP 3.x 经 `rdp_bridge` C API 接入 Swift：

- 图形（Software GDI → RGBA 帧）
- 键盘鼠标、Unicode
- 下行/上行音频通道（audin-ios、rdpsnd-ios 已编入，Swift 回调待完善）
- Display Control（接口已有）

Swift 与 C 边界：会话创建/销毁、帧回调、光标回调、输入注入、错误码映射。解码不在 UI 线程。

### 5.3 弱网

阶梯（实现中，数值可标定）：

1. 降帧  
2. 降分辨率  
3. 全彩 → 灰度 → 黑白  
4. 提高量化 / 降低色深  

用户可锁定色彩模式（底部工具栏「全彩」菜单）。

### 5.4 AirPlay 与第二屏

**已实现路径：**

1. `Info.plist` 声明多 Scene + `UIWindowSceneSessionRoleExternalDisplayNonInteractive`。  
2. `ExternalDisplaySceneDelegate` 在 `willConnect` 立即创建 `UIWindow`（避免系统仅镜像）。  
3. `ExternalDisplayManager` 检测 `UIScreen` / Scene 连接，状态：`airplayPending` → `dedicated` / `mirrored`。  
4. **扩展模式**（默认）：电视 `ExternalDesktopViewController` 显示远程帧；手机 `TouchpadView`（大触控板 + 底部左/右键与键盘）。  
5. **镜像模式**：回退，电视与手机同内容。  
6. 同一解码结果分流到主屏与外接屏，**禁止**为投屏再拉一路 RDP。

### 5.5 输入与交互

**手机直连（`RemoteDesktopView`）：**

- **鼠标指针模式**：光标层独立；捏合以光标为锚点缩放；>1× 单指平移画布；1× 长按拖移光标。  
- **直接触控模式**：绝对坐标映射。  
- 双指滚动、长按/双指轻点右键。

**电视扩展（`TouchpadView`）：**

- 单指相对移动指针；点按左键；长按右键；双指滚动。  
- 布局：触控板最大化，左/右键与键盘/功能键沉底。

**软键盘：** MS RDP 三页辅助键 + 修饰键 + QWERTY；可切系统键盘输入中文。

**硬件：** 蓝牙鼠标/触控板（间接指针）、外接键盘（GCKeyboard 映射）。

### 5.6 音频会话

- 办公听声：播放类别；开麦后切 `playAndRecord`
- 通话：`voiceChat` 或同等，系统 AEC
- 路由：听筒 / 免提可切换（会话设置）
- P0：前台保活；进后台提示通话可能中断

## 6. 关键路径与风险

| 风险 | 影响 | 缓解 |
|------|------|------|
| 远程会话无可用麦克风 | 微信对方完全听不到 | Spike；失败则 P1 Agent |
| 外接 Scene 未分配 | 只能镜像不能扩展 | SceneDelegate 立即建窗；会话内轮询；用户保持前台 |
| iOS 杀后台 | 锁屏通话中断 | P0 写进说明；P2 后台音频 |
| FreeRDP 许可与 App Store | 上架受阻 | 保留许可证声明 |
| 双屏双编码 | 弱网更差 | 单路帧分流（已实现） |
| SwiftUI 缩放坐标偏移 | 点击不准 | 远程画布改 UIKit（已实现） |

**强制 Spike（音频）**

- 环境：Win11 + RDP + 微信  
- 动作：iOS 连接并开麦克风重定向  
- 记录：远程录音设备、电平、微信通话  
- 产出：通过 / 失败 / 是否需 Agent

## 8. 工程与质量

- 语言：Swift 5/6 + C 桥接（`RDPBridge`）。  
- 最低系统：iOS 16。  
- 应用显示名：**RDP AirPlay**。  
- 日志：连接阶段可记主机与错误码；禁止默认记录密码与桌面内容。  
- 测试：真机必测麦克风、AirPlay、蓝牙键鼠；模拟器不能作为音频/外接屏验收环境。  

## 9. 发布与合规

- Info.plist 麦克风、本地网络用途与真实行为一致。  
- 隐私政策：音视频仅在用户发起的 RDP 会话中传输到用户指定主机。  
- 第三方库许可证随包或随仓库提供。
